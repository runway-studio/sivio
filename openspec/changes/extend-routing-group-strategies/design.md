# 设计
新增 strategy 枚举 order/rotate/usage，缺省 Order。三种策略都沿用同一供应商列表和故障切换器；不切换保存的客户端组别名，不改写供应商配置。Rotate 每个入站请求轮换首选，备用沿循环顺序；Usage 按配置成员的本机调度计数排序，同值按配置优先级稳定排序。
SQLite 事务串行化首选预留与游标推进，避免并发全选同一成员。状态包含有序成员指纹，成员或模型变化时重置；重命名和策略变化不重置。调度前核对配置，拒绝陈旧快照；旧请求后续故障切换只更新相同指纹的状态。首选预留包含失败、熔断跳过或取消，备用在实际调度时计数，不按响应成功率、token 或账单余额计数。
决策 Selection 保存排序前计数、排序后成员、策略原因；既有 group 和 attempts 保留，旧记录缺少 selection 时仍可读。运行计数为设备本地数据，随普通备份保存、WebDAV 同步跳过并保留本机行。全程测试使用隔离 HOME、本机测试 HTTP 服务，不发真实模型请求。
