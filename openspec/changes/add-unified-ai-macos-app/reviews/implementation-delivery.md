## 真机结果与清理

- RUN13 / helper 9：真实 TUN HTTP、DNS、超过 100 秒续约通过；有效 lease 强杀 helper 后新内核和请求恢复；冻结 35 秒再强杀后，过期内核未复活，测试 utun 被移除。
- 发现失焦暂停轮询可能延迟故障标记，已修复为关键状态事件主动刷新。RUN14 只强杀其已验证普通内核子进程，无 UI 操作的情况下即显示运行失败与清理入口；已清理。
- RUN14 App 经用户认证登记后，真实 TUN HTTP/DNS 再次通过。RUN16 的 helper 二进制与该版本完全相同；本轮没有重新启用用户网络订阅或宣称重新跑过全部 TUN 矩阵。
- 初次 scutil 比较混用了沙箱空字典和宿主数据，该测量无效，报告保留修正；重新使用宿主基线后，动态代理和持久配置摘要一致。结束时网络停止、TUN/系统代理偏好关闭、原接口与代理恢复、两个自有夹具停止。

## 本轮性能与恢复补验

- 5 次前台新进程启动 p95 3.311 秒；普通空闲 600 秒 CPU 1.033% 单核、峰值 RSS 178.91 MiB。
- 10,000 会话导航重挂 p95 从 418.1 降至 33.5 ms；这是浏览器组件夹具，完整原生大数据矩阵仍保留。
- Router 本地100请求额外开销 p95 2.523 ms；20路流式持续603.72秒，12,000帧无丢失/串流，20次取消均释放上游。
- 九阶段真实 SIGKILL 恢复、隔离64 MiB磁盘满和只读目录保护通过；修复恢复前创建空目录的副作用。
- 原生检查发现工具菜单并发刷新重复入口，已串行化主线程替换并清除重复项；启动后已观察到单一网络入口；完整初始化及两次窗口销毁/重建后均保持单一入口，窗口恢复正常。

- 轻量模式首次600秒采样CPU 0.948%、峰值RSS 116.52 MiB，但两个XPC退出使进程集合变化，未判通过；第二次被系统休眠打断，已作废。采样器新增墙钟/单调时钟偏差检测。最终RUN16先稳定130秒后连续采样600.09秒：CPU 1.240%单核、峰值RSS 93.25 MiB、进程集合不变、无时钟跳变，轻量资源门槛通过；原无效记录继续保留。
- RUN16线程采样确认网络初始化阻塞在SecItemCopyMatching。前台正常重启使系统授权进程出现，用户完成授权后恢复；helper身份登记和两次窗口复验已通过。不绕过Keychain，也不以默认直连掩盖不可用状态。恢复方法见 [钥匙串恢复说明](../../../../docs/implementation/keychain-recovery.md)。

方法、排除样本和边界见 [性能与恢复报告](performance-recovery-run15.md)。

1. Intel/macOS 12 真机、干净机安装升级卸载和睡眠/网络服务切换矩阵缺少环境或完整证据；Intel 按用户要求继续未通过。
2. 真实 AI 授权与调用按用户选择稍后登录，mock 结果不替代 live 验收。
3. T01 逐操作/字段/客户端组合、F01–F36 完整情景、所有恢复故障点及完整原生大型数据矩阵尚未全部验收；本轮已补齐启动、普通/轻量空闲、Router 长流与九阶段恢复证据，见下节。
4. 旧 Clash 偏好保留为结构化迁移材料，全部偏好自动映射尚未完成；原版真实大型备份与中断恢复仍待验证。
5. 原生第三方面板 WebSocket、自定义非本机代理目标、正式签名更新通道尚未完成端到端验收。
6. 810 个依赖均有许可声明；seahash 4.1.0、html-parse-stringify 3.0.1 缺少完整通知文本。部分补充上游许可来自后续版本，适用性需法律核对；未获得正式发布/法律通过结论。

最终主窗口已恢复、网络停止，用户订阅与偏好摘要未变，系统代理及接口与原基线一致；临时防休眠进程已退出。当前宿主可用空间约414 MiB，后续构建需要先释放空间，本轮已生成的安装包保持有效。

本报告是最终打包后的证据与风险结论。后续应沿这些具体验收项推进，不能把本轮内部包标记为完整提案验收通过。
