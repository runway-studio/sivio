## 1. 布局与范围

将现有主导航外侧增加一列领域导航，形成「一级领域 / 二级目录 / 右侧功能内容」三栏。第三级指功能内容区，页面内仍可保留供应商、扩展配置等业务标签，不再增加第三根侧栏。

一级只包含 **概览、网络、模型**，顺序固定。Clash Verge Rev 能力归入网络；CC Switch 能力归入模型。概览负责汇总和跳转。现有功能范围、业务行为和验收缺口均保留。

沿用已确认的 SI Assist Logo、iTokens 紫色、白底和冷灰卡片。二级目录沿用当前 App 的图标与文字行、紫色选中态、分隔线、上方应用列表滚动、下方资源菜单固定及底部设置结构。原型中的应用图标为缩写占位；正式实现继续复用现有 AppGlyph。

| 区域 | 展开尺寸 | 交互 |
| --- | --- | --- |
| 一级领域栏 | 84 px | 图标加短名称，始终显示；只有一个领域高亮 |
| 二级目录 | 218 px；收起为 72 px | 仅此栏可折叠；图标保留完整名称提示与无障碍名称 |
| 内容区 | 剩余宽度 | 顶部面包屑、页面标题与操作；内容独立滚动 |

按 1280×900 和 960×720 桌面窗口设计。960 px 宽时内容区为 658 px，不产生整页横向溢出；长表格允许自身水平滚动。低于桌面最小宽度的网页预览可横向浏览，不作为手机布局承诺。

| 网络 | 规则 | 规则管理与命中查看 |
| 网络 | 连接 | 当前连接、筛选和关闭连接 |
| 网络 | 日志 | 内核日志与过滤 |
| 网络 | 检测 | 网络出口、连通性及相关检测 |

| 模型 | Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi、MiniMax Code | 沿用当前应用顺序；选中后直接显示该工具的供应商和工具配置，移除右侧重复的工具选择器 |

原侧栏中的概览、网络从模型目录移除。应用显示/隐藏偏好和排序继续复用；原型为方便评审展示全部十工具。项目快照、专属工具配置等原有能力仍保留既有页面入口，不借本轮导航设计扩大或缩减范围。已有旧设计的项目示意页仍可通过搜索访问，正式映射应以当前产品入口台账为准。

## 3. 关键交互

1. 首次进入：概览 → 工作台；第一次打开网络默认订阅，第一次打开模型默认已有选中工具，没有记录时为 Claude Code。原型默认 Claude Code。
2. 领域记忆：每个领域记住最近的二级页面。模型 → Codex → 网络 → 节点 → 模型回到 Codex；再次打开网络回到节点。点击已选领域不重置页面。
3. 页面记忆：正式实现保留工具选择、页面内标签、筛选、列表滚动与编辑草稿。仅持久化领域、二级页面和折叠偏好等非敏感位置；不把凭据或草稿写入路由。原型演示领域、工具、模式、供应商选择及目录滚动的内存状态，刷新不保证恢复全部草稿。
4. 设置往返：底部应用设置在所有领域可用，打开后一级保留来源领域，二级切换为设置目录，并显示「返回概览/网络/模型」。返回恢复原页面；直接点击一级可跳到其他领域。网络二级「设置」明确标为网络设置，与底部应用设置区分。
5. 跨域跳转：概览卡片、搜索、托盘等定位操作同时更新一级高亮、二级高亮和内容；普通领域切换恢复历史，明确目标的跳转优先使用目标。历史返回不能只改变内容、不更新侧栏。
6. 未保存编辑：换领域、换二级、快捷键和历史返回共用现有未保存提醒，提供「继续编辑 / 放弃并离开 / 保存并离开」；保存失败留在当前页。不能因布局切换静默丢弃表单。原型没有重新实现完整草稿生命周期，此项保留为实施验收。
7. 服务持续运行：导航只切换视图，不启动或停止网络、helper、AI 路由或同步任务。离开日志/流量页停止该页的高频显示更新，不中断底层任务。
8. 故障与空态：错误、离线、未安装 helper、空订阅或未配置模型均显示在所属内容区；一级和二级始终可用。当前选择被隐藏/移除时回退到可见应用或应用管理页，并提示原因。
9. 键盘：Tab 顺序为一级、二级、全局入口、内容；Enter/Space 激活，切换后焦点移到内容标题区域；提供跳到主内容。沿用 ⌘K 搜索及 ⌘, 设置，不新增易冲突快捷键。收起/展开后焦点留在折叠按钮。

## 4. 实施拆分（已接入）

| 顺序 | 改动 | 明确验收 |
| --- | --- | --- |
| N1 导航状态 | 在现有前端 View 状态上增加 domain 与领域内最近位置；统一跳转函数，不引入新的路由库 | 所有已有 View 有映射；旧深链、托盘、搜索可达；领域高亮与内容一致 |
| N2 壳与目录 | 拆分领域栏和二级目录，复用 Sidebar、AppGlyph、应用显示偏好及折叠 hook | 三个固定领域；十工具和六资源菜单不丢；折叠后设置可达；960×720 无整页横向溢出 |
| N3 页面接入 | NetworkWorkspace 的横向业务导航移到二级；模型复用现有页面，不重复工具选择 | 网络八个菜单可达；工具内部标签仍有效；全局设置返回来源位置 |
| N4 状态与回归 | 统一离开守卫、滚动/筛选恢复、错误边界和按可见性暂停页面轮询 | 草稿阻止误离开；网络/AI 任务不断；切换不增加监听、内核或高频定时器；浅/深色与键盘通过 |

主要涉及 `app/src/App.tsx`、`app/src/components/shell/Sidebar.tsx`、`app/src/hooks/useSidebarCollapsed.ts`、`app/src/components/network/NetworkWorkspace.tsx`。无需修改 Rust/helper 协议、存储所有权或 AI/网络代理行为。导航状态保持简单的显式映射，不引入插件系统或新的状态管理框架。

## 5. 设计审查与边界

| 质量门 | 设计结论 | 依据 |
| --- | --- | --- |
| 需求 | 通过设计审查 | 概览/网络/模型同级；模型保持当前应用和资源菜单；网络统一容纳原 Clash 功能 |
| 架构 | 通过设计审查 | 仅重组前端视图与状态；运行服务不随栏目生命周期变化；全局设置共享领域状态 |
| 可实施性 | 通过设计审查 | N1–N4 可直接拆分；有最小窗口、位置记忆、草稿、旧入口和后台任务的明确验收标准 |

浏览器检查覆盖主域往返、Codex/节点位置记忆、设置返回、折叠后设置入口、主题切换、历史返回及 960 px 宽布局。详见 [validation.json](validation.json)。检查中修复了折叠后设置入口被隐藏、模型标题未跟随工具、路由载入时供应商示例错配三处问题。

剩余风险：三个领域加目录会占用更多横向空间；长工具列表在小窗口需要滚动。原型复用旧页面模拟，未替代全部业务编辑器及未保存状态的实装验收。真实 App 中旧深链、托盘、隐藏应用、轮询和窗口重建需在 N4 回归。现有 Intel 真机与真实账号验收仍保持未通过/待执行，不因本轮设计而改变。


## 6. 实施对齐（2026-10-16）

- 保持现有编辑器操作：离开提醒沿用「继续编辑 / 放弃并离开」，保存仍在原页面执行；未新增统一的「保存并离开」按钮，避免绕过各编辑器的校验与异步保存。取消离开和保存失败仍保留原页内容。
- 原生 App 沿用设置返回、Esc 与托盘/旧 View 定位，不新增浏览器式历史栏；上文的浏览器前进/后退为 HTML 原型能力。F01 回归使用原生设置返回及现有定位入口。
- 已增加领域最近页、网络页签、工具选择、供应商/网络搜索和相应列表滚动的记忆。其他业务页内部筛选和模式切换沿用既有行为；未缓存整个隐藏页面，也不会为保留视图持续运行隐藏页轮询。
- 一级领域固定；原菜单排序偏好继续保存完整兼容结构，设置页仅展示可调整的模型资源菜单。
