## Context

### 已核实的源码依据

- `vendor/upstream/cc-switch/src-tauri/src/database/dao/providers.rs`：`save_provider` 直接将 `settings_config` / `meta` 序列化到 SQLite，读取使用 `serde_json::from_str`。
- `vendor/upstream/cc-switch/src-tauri/src/services/subscription.rs`：Claude Code 和 Codex 官方登录有读取 Keychain 的分支，不能将普通配置免授权扩大解释为所有功能完全不用钥匙串。
- `app/src-tauri/src/credential_vault.rs`：按字段名保护 `env/config/url/token/...`，每次写入创建新的 UUID 条目；缓存仅在当前进程生效。
- `app/src-tauri/src/database/credentials.rs`：当前启动会把明文旧配置重新封装为钥匙串引用；改造必须同步改变这条路径，避免迁移后再次封装。
- `app/src-tauri/src/settings.rs` 和 `network/repository.rs`：文件偏好与网络配置同样依赖凭据反序列化，仅改供应商 DAO 不足以消除弹窗。

## Goals / Non-Goals

- 新数据和完成迁移的数据：日常启动、切换供应商/网络配置、保存、重启不访问 Sivio 自有 Keychain。
- 旧数据：可见、可取消、可恢复迁移，不静默覆盖默认值，不要求每次启动重做迁移。
- 不扩大其他应用钥匙串条目的权限，不更改 Claude/Codex 的官方登录机制，不自动操作用户正在运行的网络服务。

## Decisions

### 本地存储

采用 CC Switch 的本地序列化方案，继续使用现有 SQLite 和设置文件，避免额外的第二份凭据库。正常序列化不产生新的 `$siCredential` 引用。对于遗留引用，正常读取返回明确的待迁移状态，不自动触发系统授权；专门的迁移入口负责解引用。

保护目录 0700、数据库/JSON/临时文件/本地备份 0600，并核对 SQLite journal/WAL/SHM 的权限。原子写入在创建临时文件时即设置权限，拒绝意外符号链接，不修改应用数据根之外的目录权限。普通文件权限不能隔离同一账户下的其他进程；这是本方案明确的取舍，不称为加密存储。

### 旧数据迁移

1. 启动只扫描引用和计数，不读取钥匙串内容；UI 显示待迁移状态，阻止对未成功加载的数据进行默认值覆盖。
2. 用户主动启动迁移后，先完成受限权限的原始快照备份，备份失败则不开始写入。
3. 按完整文档读取所需旧引用，合并相同引用的并发访问。全部字段成功解析后才提交该文档；SQLite 使用原始值 CAS，文件使用修订检查和原子替换。
4. 已提交的文档及迁移进度持久化；拒绝授权、失败或取消后停止自动重试。进度记录不含明文凭据，下一次只处理未完成文档。
5. 不删除原 Keychain 条目。回滚恢复对应原始快照及进度；恢复旧备份时重新检测引用，不能将缺失引用解释为凭据为空。
6. 对无法授权的条目提供现有只读导入/重新填写路径，保留用户对冲突和来源的选择；不在后台自动读取其他应用的账户或订阅。

不能绕过 macOS 对旧条目的授权，也不能保证迁移只需输入一次密码。目标是将授权限制在明确的迁移阶段，消除完成迁移后的日常重复授权。

### 导出与备份

本地完整备份包含可读凭据，使用受限目录和文件权限，不被当作默认可上传载荷。可移植导出和云同步继续经过 `portable_credentials` 清洗；显式包含秘密的载荷保持现有认证加密。检查全部复制/归档路径，防止本地明文存储变化导致原始数据库或设置文件绕过清洗被上传。

## Risks / Trade-offs

- 同用户进程可以读取本地凭据；这是免自有 Keychain 访问的代价。
- 旧条目仍可能逐条要求授权；迁移进度持久化避免已成功文档被反复处理。
- 部分迁移和旧备份恢复形成混合数据；明确的遗留标记检测、原子文档提交、回滚和异常测试覆盖这些状态。
- 官方登录及 helper 安装仍可能出现独立系统授权，不归入普通配置免授权承诺。

## Migration Plan

获批后先更新活动 F31 规范，再实现存储边界、权限、迁移和 UI。使用合成数据测试迁移成功、拒绝、中断、冲突、磁盘失败、重启及导出；在临时目录和隔离钥匙串验证，不触碰真实凭据。构建新 App 后由用户主动迁移真实数据，并完成实际重启免弹窗验收。
