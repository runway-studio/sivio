# 三道质量门与停止规则

本次仅规划。根代理编写提案，三个独立子代理分别执行需求、架构和实施可行性审查；不以作者自评替代独立审查。审查使用当前仓库和本聊天范围，不消费真实用户配置或外部账号。

- P0：会导致严重破坏/不可接受行为的设计缺陷；P1：行为冲突、关键决策缺失、无法按依赖实施/验收，均阻止规划通过。
- P2：不改变关键行为、已有可实现默认或退路的改进；P3仅措辞。不得把实际阻塞降级为“剩余风险”。
- 全量第一轮→只修有证据的问题→第二轮复核问题及直接副作用。最多4轮防止无限润色；达到上限仍有阻塞只能报告未通过，不伪造成功。
- 成功停止同时要求：三门无未关闭P0/P1、九方向完整覆盖、每任务可执行验收、OpenSpec strict/链接/场景映射/依赖检查通过、无尚待作出的核心产品/架构决策。低收益措辞不继续循环。
- 内部评分采用proposal权重：目标20、用户流程20、范围15、验收15、风险依赖10、实施可操作性15、表达5。评分是审查信心估计，不是产品实测；P1未关闭上限84、P0上限69。达到90且无阻塞才可质量达标停止。
- 本轮未运行任何业务测试/编译/安装/真实调用；未来实施与公开发布仍需独立授权和对应验收，任务全部未勾选。
