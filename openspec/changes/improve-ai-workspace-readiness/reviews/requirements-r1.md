## 阻塞问题

### REQ-01 [P1] 明确游标保护的开关、默认值和迁移矩阵

- 证据：design.md:49 只定义 `continuity=request/session`；design.md:53 要求“凡路由组请求”带 `previous_response_id` 均检查归属；design.md:96 又限定“仅在启用本次组连续性保护后启用”。specs/model-routing/spec.md 的 R09 同样使用未定义的“启用连续性保护”。
- 影响：实现者无法判断旧 request 组是否升级即拒绝已有续接，或新 request 组是否仍允许不受保护的跨供应商游标。这直接影响向后兼容和功能验收。
- 最小修订：选择一个确定模型，例如独立 `cursorProtection` 开关或明确由 `continuity` 推导；列出旧/新组 × request/session 的默认值、可选组合和 UI 提示。同步设计、R09、T12/J04。
- 关闭验收：四类默认/迁移行为唯一；保护关闭、开启且归属正确、开启但归属未知三类场景有明确结果；不再出现“全部组”与“仅启用组”的矛盾。

### REQ-02 [P1] 区分可以保留在途请求的环境热切与需要排空的变更

- 证据：design.md:79 将环境应用统一放入 quiesced 流程，停止受影响网关并等待最多 30 秒；R11 的在途场景规定未排空则 busy。R12（specs/project-environments/spec.md:32）及 acceptance.md:19 则要求 A 请求未结束时切换 B 成功，新请求采用 B。
- 影响：相同操作同时要求“先排空才能提交”和“在途未结束即可提交”，实施者无法确定提交时机、作用范围和 J06 的预期。
- 最小修订：确定哪些仅改变本机请求快照的字段允许热切，哪些涉及客户端文件/MCP/Skills/模式变更必须排空；或者统一采用排空并调整 R12/J06 的示例。不要为满足两种文案引入额外复杂事务。
- 关闭验收：给出一组可热切和一组需排空的确定测试（若全部排空则只保留后一组），说明活动指针何时改变以及被拒绝/在途请求归属，spec/design/task/J06 一致。

### REQ-03 [P1] 零预算与 observe 模式的行为冲突

- 证据：specs/budget-controls/spec.md:8 与 design.md:57 无条件规定 `0` 禁止新付费派发；R14/design.md:59 又规定 observe 警告后继续，默认模式为 observe。
- 影响：保存“0 + observe”会被实现为阻断或仅提醒，两者都能从规范得到依据；用户可能误以为已经停用消费。
- 最小修订：提供 mode × limit 的小型行为表。建议 0 表示立即达到阈值，observe 仍只提醒、block_new 才阻断；若选择零值强制阻断，则保存时显式切换模式并提示，不能隐式覆盖 observe 契约。
- 关闭验收：空限额、0、正数在两个模式下结果唯一；UI 文案与 T11/J05 对应场景一致。

### REQ-04 [P1] 新预算账本的本周期既有消费基线未定义

- 证据：T10 新增尝试账本；design.md:59 以该账本已观测费用作准入依据；R23 只规定配置恢复不重置消费。现有 `services/usage_stats.rs::check_provider_limits` 已将 `proxy_request_logs` 和 `usage_daily_rollups` 的当日/月消费相加，但本提案没有规定升级或首次开启 block_new 时怎样纳入这些已有消费。
- 影响：若新表从空开始，用户今天已经花费的金额可能被视作零；若同时合并旧统计与新账本，又可能重复计费。预算日/月语义和“不重置消费”无法验收。
- 最小修订：定义账本启用的固定截断点/覆盖起点及一次性 opening balance；可信旧金额作为基线，无法证明完整的部分标 unknown，并说明如何在 UI 呈现。也可明确只从启用开始计费，但不能把不完整周期标为完整日/月预算。
- 关闭验收：升级前本日/月存在已知消费、部分记录已 rollup、重复迁移、无价旧记录四类夹具；升级后既不清零也不双计，周期覆盖不足可见，block_new 结果确定。

## 非阻塞改进

### REQ-05 [P2] 给未知费用阻断提供可操作的解除说明

- 证据：R14 会在 unknown 后阻止新派发；R15 提到补录 usage/显式调整，R23 提到“直到显式核对或周期结转”，但没有对应的界面入口和核对结果规则。
- 建议：首版至少展示受影响周期和原因，允许用户明确切回 observe 或等待周期结转；若提供核对/调整，写清保留原记录和调整依据。无须引入账单对账平台。
- 非阻塞理由：已有 observe/block_new 设置提供可用的恢复控制，不影响先实施底层准入；但在预算功能交付前应补入 UI 验收。
