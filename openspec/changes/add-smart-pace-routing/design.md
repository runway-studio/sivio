# 设计
沿用 Magpie 公布的策略含义（https://github.com/yetone/magpie#routing-groups），不引入嵌套组、粘性会话或跨供应商私有响应 ID 迁移。

额度来自真实路由供应商的凭据：已识别官方域名的原生编程套餐查询，以及明确绑定账号的 Codex OAuth 查询。不会使用应用级 CLI 订阅缓存，不会把余额、脚本展示文本或本机次数当成额度；不能证明与推理密钥同账号的独立控制面额度不接入。查询不依赖页面打开；Smart/Pace 请求触发，其他策略不探测。

缓存仅存于进程，按客户端、供应商和凭据/绑定/查询配置指纹隔离，最多 256 项。成功缓存 60 秒，失败缓存 15 秒；过期查询最大等待 3 秒，重置时间到达强制刷新。并发请求合并同一项查询。网络操作在 SQLite 锁外；查询后调度仍核对组和供应商配置以免陈旧结果参与选路。重启后重新获取，不同步凭据或额度快照。

Smart 在有效窗口均未耗尽的成员中按最早未来重置时间排序；Pace 必须有明确周窗口，以周剩余百分比/距重置小时数降序，分母至少一分钟；多个周限额取最保守速率。同分按配置优先级。任一有效窗口耗尽的成员在末尾，允许上游自身付费超额/恢复策略作为最终兜底。缺失或不适用的数据排在有效候选之后、耗尽之前，保持配置优先级。没有可评分成员时明确记录回落 Order（不是静默声称 Smart 生效）。超过五分钟、未来时间戳、非法数值和已过重置点的快照不评分。

决策只保存来源、采样时间、可用状态、窗口百分比/重置时间/速率和候选次序，不保存密钥、账号标识、URL 或上游错误正文。已有计数与组选择语义保留。
