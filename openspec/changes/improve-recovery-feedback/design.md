## Decisions
- Runtime 拥有恢复进度；快照单独输出 recoveryStatus/recoveryRequired，不改变 phase 的既有契约。清理失败优先于自动重连显示；停止/新运行重置进度，迟到循环不得改变新 generation。
- 复用原有三次重连和无主网络服务等待，不增加重启、强抢代理、直连回退等行为。
- 首页处理入口跳转现有网络设置；生命周期写入仍由已有唯一控制入口执行。
- 模型阶段复用 useWorkspaceReadiness，错误不显示旧成功。保留既有 ClientOnboarding 打开/验证操作及收费确认。
- 按 ths-react-best-practices 验收流程检查异步状态与实际调用方；新增跨 Rust/TS 只读快照契约安排独立复核。

## Acceptance
- 恢复状态覆盖重试、等待网络、用尽重试、清理失败、停止/新代次；已有代理接管不显示为全面正常。
- 模型保存、读取、验证三个阶段独立；读取不可观测明确提示新会话验证，草稿期间后续操作禁用。
- 原生 UI 工具首次按名称连接超时，后以完整 bundle 路径访问成功；该结果不是 App 故障结论。隔离测试不能替代物理换网、TUN 和真实账户验收。

## Native finding
- 用户明确授权临时停止 Clash、改用 Sivio，结束恢复 Clash；允许短时 Wi-Fi 中断及睡眠，并约定手动唤醒。
- 首轮物理 Wi-Fi 断开/恢复后，通过 Sivio 的目标请求恢复，但出现代理外部修改告警。首轮期间存在用户并行操作，不以时间关联单独认定原因。
- 代码确认 NoActiveNetworkService 被折叠成未知读取失败、永久锁存 tripped。修复将该明确错误作为等待观测，下一次健康 tick 重试；不主动写代理，不放宽未知错误或真实外部修改保护。停止/新运行仍重置 Guard。
- 等待提示仅用于仍运行的 guard；失败且重连耗尽时显示实际错误。新增独立恢复/外部修改/未知错误回归。
