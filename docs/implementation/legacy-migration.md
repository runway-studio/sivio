# 原应用迁移

设置 → 数据 →「从 CC Switch / Clash Verge Rev 迁移」提供默认目录只读扫描、原生目录/备份选择、冲突预览和独立的确认导入步骤。默认保留相同标识的现有实体，勾选替换会使预览失效并重新计算。

支持固定基线 CC Switch 的 SQL 导出、SQLite 数据文件和包含 `cc-switch.db` / `skills/` 的数据目录；SQLite 与 WAL 先复制到私有暂存目录，原路径不交给 SQLite 打开。支持 Clash Verge Rev 的 ZIP 备份与包含 `profiles.yaml`、`profiles/` 的数据目录。来源在扫描中发生变化时拒绝预览。SQL 受 authorizer 保护，触发器、虚拟表、ATTACH/外部写入和超前 schema 均不能进入发布流程；ZIP 拒绝路径越界、重复路径和符号链接，输入总量限制为 512 MiB / 30,000 文件 / 128 层。

预览只返回路径、数量、冲突策略和提示，不返回配置正文或凭据。预览令牌绑定来源内容、文件 owner 权限、SI Assist 数据库与 Skills 修订。确认时重新构建并核对令牌，恢复 journal 和数据库 CAS 负责发布与中断恢复。Skills 复制保留现有链接本身，不跟随到其他项目；来源链接要求先整理成独立备份。文件导入保留 owner 的可执行位并清除 group/other 权限。

CC 数据合并保留配置的未知字段，使用原实体标识实现重复导入不增加实体；供应商、MCP、提示词、Skills 和仓库导入后均不启用。原本机 OAuth 会话、客户端路径覆盖、代理所有权和应用更新设置不被带入。目录导入可合并 Skills 正文，单独 SQL/DB 文件只包含数据库对象。相同名称而标识不同的对象仍被视为不同实体，应在导入后检查。

Clash 订阅使用原 UID 派生稳定 SI Assist ID；YAML、独立 Merge/Script/序列、原全局增强和请求参数一起保留。迁移时不执行 JS、不获取订阅、不启动内核；原全局增强随订阅保存，避免改变已有 SI Assist 订阅。节点选择被带入订阅的选择记录；定时更新默认为关闭，档案默认未选中。原配置、DNS 与偏好按结构化对象保存到加密网络记录中，便于后续映射和审查；它们不会自动覆盖 SI Assist 端口、TUN、系统代理或更新通道。**尚不能将这一步称为所有 Clash 偏好的自动迁移完成。**

夹具证据：`build/reports/legacy-migration-schema-fixed.log` 四项通过，包括活动 WAL、原来源内容不变、重复/冲突、来源及目标变化、损坏/超前 schema/越界、脚本不执行；界面回归 `legacy-migration-ui-regression.log` 共 24 项通过（迁移 3、同步隐私 3、设置 18）。后续新增网络行为以最终全集回归为准。原版真机导出的大型实际备份与完整断电/磁盘满矩阵仍待验收。
