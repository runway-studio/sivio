# Claude Code 路由模型一致性修复

日期：2026-10-19

后续更新：本页记录首轮修复。路由中的主模型现已改为写入顶层 `model`，不再保留接管配置的 `ANTHROPIC_MODEL`；并增加独立的客户端选择持久化。最终行为与验收见 [模型选择与网关总览](model-selection-gateway-overview.md)。

## 问题与修复

用户反馈：从直连切到路由后，Claude Code 选择的模型与配置不同。

1. 路由投影原先删除 `ANTHROPIC_MODEL` 和供应商已保存的顶层 `model`，只写角色别名。默认模型因此可能改变。现在路由保留这两项；聚合继续使用其独立模型列表。
2. 原映射器先按名称中的 Sonnet / Opus / Haiku / Fable 匹配角色，再将其他名称改成兜底模型。直连会话已经选择的真实模型、包含角色名称的子代理模型因此可能被再次映射。现在配置中明确列出的模型 ID 优先原样通过，角色别名再按档位映射，未知 ID 仍按原规则回落。
3. 当真实模型名与内部角色别名重名、但它们指向不同模型时，投影为内部别名追加 `-route`，避免默认模型或跨档配置抢占该角色。显示名称继续使用供应商配置；1M 标记仍沿用现有转发处理。
4. 模型表单独立于高级选项显示，并明确默认模型在路由中的作用。
5. 模型列表请求按认证字段发送 Bearer 或 x-api-key，Anthropic 请求带版本头；更换端点、凭据或协议后丢弃旧请求结果。
6. 编辑供应商时隔离投影和草稿，避免复用另一家的模型；修复空操作后忽略外部模型更新、编辑其他字段时丢失旧版小模型映射的问题。

## 验证范围

- 前端：模型编辑、列表请求、切换供应商、模式切换、聚合表单及保存操作的定向回归。
- Rust：模型映射、路由投影及模型相关回归；临时配置和本机测试代理验证进入路由、保存新模型、退出路由。
- TypeScript 类型检查、格式检查、生产前端构建。
- 未调用用户真实上游 API；未改写用户的供应商库或 Claude Code 配置；未安装或替换正在运行的应用。

结果：120 项前端测试通过；Rust 模型相关 351 项、模式控制器 117 项、Claude 投影 13 项、契约 3 项全部通过（去重 466 项）。类型检查、前后端格式检查和生产前端构建通过。首次沙箱测试受本地端口绑定限制，已获准使用本机测试端口重跑通过。
