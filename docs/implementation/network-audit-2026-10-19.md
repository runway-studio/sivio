# 网络功能排查与修复（2026-10-19）

本轮按用户要求排查并修复现有网络行为，适用已批准的 F19/F21/F22/F24/F26；不新增能力或扩大 helper 权限。排查覆盖配置读写与恢复、订阅刷新、自动测速、代理所有权、内核启停、失败恢复和网络界面。修复前原有 66 项网络测试通过，缺失的场景增加回归覆盖。

## 问题与修复

1. **首次加载失败后重试无效。** 后端 `ready=false` 会拒绝 snapshot，而“重试”只重发 snapshot。现在显式重试执行配置初始化，仓库可对同一数据库重新连接；成功后只启动一份后台任务。仍不可读取时保持禁用，不自动反复重试；已有缓存但刷新失败时也保留重试入口。
2. **启动时界面查询与初始化竞态。** 首次 snapshot 如果早于后端加载，前端因错误停止轮询；后端完成后没有通知。现在初始化成功发送运行状态事件，触发一次重新查询。
3. **自动测速重置手选节点并阻塞启停。** 固定 Mihomo 的 `/group/.../delay` 对非 Selector 的可选分组调用 `ForceSet("")`；后台旧实现还在整个请求期间占有生命周期锁。现在使用逐节点 delay、去重、四并发和 generation 核对，等待网络时释放运行锁。真实内核测试在 URLTest 强制选择 REJECT 后测速，检查手动选择字段 fixed 仍保留及运行锁可及时获取，并调用旧接口复现 fixed 被清空。
4. **订阅刷新重新争抢外部系统代理。** 旧刷新路径重启时使用默认代理策略，丢失 guard 暂停状态。现在复用设置事务的即时代理所有权检查，新订阅激活和失败回滚都保留暂停策略；无法读取系统状态时不抢回。
5. **启动或停止清理失败后可能误报恢复、重复启动。** 清理错误曾被忽略，helper 续租可能将部分失败运行时重新标记为 running。现在保留所有权与进程句柄，标记必须清理，阻止覆盖现存资源；订阅失败回滚先确认候选清理，再 CAS 恢复旧配置和启动旧内核。外部写入不覆盖，恢复失败明确报告。普通模式控制目录延迟到预检完成后创建，部分启动始终使用本轮目录清理。

## 验证与边界

证据位于 `build/reports/network-audit-*`，最终结果以对应日志及验证报告为准。回归使用合成数据、临时目录和回环监听；真实 Mihomo 验证逐节点测速、运行响应以及既有端口/DNS应用、实际代理请求与失败回滚。前端验证显式初始化重试与错误显示，并回归网络首页、节点、流量和高级设置。

没有操作用户订阅凭据、系统代理、已安装 helper 或 TUN。受管代理策略使用故障注入与已有 helper 边界测试；本轮不将普通内核测试宣称为真实 TUN、macOS 系统代理接管或 Intel 真机验收。内部包未公证，完整原始提案仍未整体验收。

最终原生网络回归 73 项通过（含2项显式运行的真实内核测试），6个网络界面测试文件46项通过；TypeScript 和 OpenSpec strict 校验通过。首次新增测试曾错误用 `now` 断言不可用节点的强制选择，保留首轮72通过/1失败日志；按 Mihomo 源码修正为 `fixed`，并补充旧接口清空该字段的实证后，最终全绿。包完整性、签名和10个对应源码一致性见 `network-audit-verification.json`。
