# Sivio 运行中保存网络设置

本轮按用户明确要求补齐 OpenSpec F24/F26：运行中可保存端口及网络设置，自动重新应用，失败恢复旧配置和原运行状态。

## 实现

- 网络设置允许运行时编辑与保存，按钮为“保存并应用”，提示连接可能短暂中断。提交期间禁用重复保存、关闭和离开；错误保留在弹窗，草稿不丢失。helper 安装/卸载继续要求停机。
- `network/settings_update.rs` 在既有 `NetworkState.write` 内串行处理：核对编辑 revision，合成实际活动订阅及增强，校验真实内核配置、helper 条件和候选端口；必要的自定义代理目标确认在停止前完成。验证期间配置被外部修改也拒绝提交。
- 校验通过后停止旧网络，确认候选内核控制通道及启用的代理监听就绪，最后 CAS 提交设置。无变化不重启；停止时保存不自动启动。
- 启动或提交失败时，先确认候选进程/会话清理完毕，再恢复旧配置与网络；配置若已被其他写入者修改则保留外部写入并明确报告恢复失败。持久化在替换后报告错误时，只允许 CAS 回滚本次精确候选。
- 恢复失败保留清理所需状态并显示 failed，租约续期不能把尚未恢复的运行时改称成功。恢复使用新 generation，旧请求不能操作新内核。原有节点选择恢复继续沿用。
- 保存无关设置及失败回滚保留系统代理的外部接管暂停状态；不会因为修改日志、DNS 等设置自动抢回系统代理。显式代理目标修改沿用原权限确认。helper 的 CAS 恢复机制保持。
- PAC/控制器任务停止后等待退出，释放监听端口；混合、HTTP、SOCKS、Redir、PAC、控制器及 DNS 的 TCP/UDP 都参与候选端口检查，运行前再次检查，不终止外部占用进程。

DNS 同时检查 TCP 接受连接与本机 UDP 错误响应，探测不查询上游解析器；DNS 不得与代理、PAC、控制器复用端口，避免内核只记录监听错误但应用误报成功。

“恢复运行状态”指旧配置、活动订阅与代理策略重新就绪；内核重启期间已断开的 TCP 连接不能复活。

事务故障注入使用生产事务入口，覆盖运行/停止、无变化、并发/过期请求、配置校验失败、部分启动失败、保存失败、替换后持久化错误、外部写入保护、候选清理失败、旧运行恢复失败、系统代理暂停策略。前端挂载测试覆盖运行中端口和 DNS 保存、提交锁定、失败草稿/重试和外部配置冲突。

真实内核测试使用随包固定摘要 Mihomo 与 ordinary supervisor、私有临时目录和临时回环端口，执行实际 HTTP 代理流量与切换/回滚。此路径不调用已安装 helper，不修改用户配置、系统代理或 TUN；不把 ordinary 路径通过宣称为本轮 helper/TUN 真机验收通过。

交付沿用 Apple Silicon 内部 ad-hoc 签名包；未公证，Intel 真机和整个原始功能矩阵沿用既有未验收状态。
