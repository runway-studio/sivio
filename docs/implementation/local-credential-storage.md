# 本地凭据存储与旧数据迁移

2026-10-19，用户批准 `update-local-credential-storage`，参考仓库内 CC Switch 基线实施。

## 用户可见变化

- 新建及已迁移的供应商、MCP、网络订阅、出站代理及偏好保存在本机 SQLite/JSON；正常打开、保存和切换配置不读取 Sivio 自有 Keychain。
- 有权以当前账户身份读取这些文件的进程可以读取凭据。应用私有目录为0700、数据库/设置/备份文件为0600；应用启动前设置私有 umask，SQLite 附属文件与临时输出沿用该权限边界。这是账户文件权限保护，不是加密存储。
- 旧数据仍包含 `$siCredential` 时，窗口显示迁移提示。检查状态只读取引用，不触发系统授权。用户主动开始后，先保存原始 SQL 与设置/网络文件备份，再逐份配置迁移。
- 旧系统条目可能仍需多次授权。拒绝、暂停、读取失败或写入冲突会停止迁移；已经提交的完整文档不重复迁移。正在显示的系统弹窗可选择拒绝；应用的暂停请求在系统调用返回后生效。
- 迁移完成后点击“重启应用”，重新加载设置、网络状态及供应商。不会自动更改网络服务或原应用数据，不删除旧 Keychain 条目。
- 无法读取旧凭据时可以进入“数据”页面从 CC Switch/Clash Verge 或 SQL 备份导入。Clash 旧配置整份不可读时，必须明确勾选替换并确认预览，才会以导入来源重建网络配置；原配置由恢复日志/备份保存。设备偏好不从其他应用复制，仍需完成相应旧条目的迁移或从自己的设置备份恢复。
- 普通 SQL 导出不含凭据和本地运行日志。完整本机备份保留本地数据，含秘密可移植包/云同步继续使用现有认证加密和显式口令设置。界面已将“记住口令”的存储位置改为本机配置文件。
- Claude/Codex 官方登录及特权服务安装自己的系统授权机制保持原样。

## 数据与恢复边界

`credential_vault` 正常序列化/反序列化不调用 Keychain API。唯一读取自有旧条目的入口位于显式迁移模块，使用调用方注入的读取函数解开旧引用；没有全局“允许钥匙串”开关，后台读取不能借用迁移权限。

SQLite 按完整文档进行原始值 CAS。文件使用共享私有写入锁、修订检查、0600暂存文件和原子替换。取消/拒绝发生在提交前时保留原文档；检查点写入失败后，已提交文档自身即是持久进度，重试只扫描尚存的旧引用。迁移读取不持有数据库锁；运行期间抑制自动云同步并与恢复流程共用互斥。

每次迁移的原始备份位于 AI 数据目录下 `credential-migration/<随机标识>/`，包括 `database.sql`、存在的原始设置/网络目录文件及不含凭据的 `progress.json`。保留原 Keychain 条目和备份。恢复整个 SQL 可使用数据页面的 SQL 导入；文件备份用于对应设置恢复，恢复前需退出 App 并核对目标路径。恢复旧引用后，新版本仍会显示待迁移状态。

网络新增/更新通过有界进程暂存衔接已有校验和 SQLite CAS，成功后删除暂存值，不再先写一个 Keychain 条目再复制到数据库。历史网络专用 Keychain 条目只在主动迁移时读取。

## 验证与范围

自动检查使用合成凭据及临时数据目录，不读取用户真实钥匙串条目。

- 界面：迁移提示、明确启动、拒绝不重试、暂停、导入入口，以及网络页面/同步隐私回归。
- Rust：本地读写、遗留引用拒绝隐式读取、文档级迁移/冲突、部分失败后继续、检查点失败后不重复处理、权限/符号链接、文件冲突/写入失败、默认导出去秘密、旧备份导入和两种云同步的加密恢复。
- 隔离 macOS Keychain：禁用系统交互，以测试条目迁移到本地文件，锁定测试钥匙串，确认旧条目读取被拒绝而新本地配置多次重新读取成功。测试结束删除测试钥匙串。
- 构建：最终 Apple Silicon App/ZIP/TAR 与签名、归档完整性及包内对应源码检查。

当前定向原生回归 142 项（去重）通过，界面33项通过，类型检查及两份OpenSpec strict校验通过，隔离钥匙串迁移另1项通过。2项原有性能手动测试未运行。具体结果记录在 `build/reports/local-credentials-*`。真实旧凭据由用户在新版本中自行选择迁移；未将模拟测试或隔离钥匙串测试表述为真实用户迁移已完成。未执行物理磁盘写满、Intel真机或第三方官方登录验收；内部包未公证，完整原始提案仍未验收通过。
