# 内部包钥匙串授权恢复

适用：SI Assist 内部 ad-hoc 包升级后，网络工作区长时间显示“正在加载网络配置”，系统没有出现预期的钥匙串授权窗口。当前构建更换代码身份时，macOS 可能要求重新允许本 App 访问其已保存凭据。这个授权与 AI 账号登录、独立 helper 的管理员安装认证是不同步骤。

## 已验证恢复步骤

1. 保持网络停止，不清空订阅或数据库，不删除钥匙串项目。
2. 正常退出 SI Assist，再从 Finder 前台打开同一个最终 App。
3. 若 macOS 出现 SI Assist 的钥匙串访问提示，在系统窗口自行核对应用并完成授权；不把密码提供给聊天或脚本，不扩大到所有应用。
4. 返回网络工作区，确认订阅列表正常显示，系统代理与 TUN 偏好仍为原值。
5. 只有界面提示“需要登记当前 App”时，再使用“安装 / 修复服务”登记当前 App 身份到 SI Assist 自己的 helper。系统管理员认证也由用户在系统窗口完成。

RUN16 已按以上步骤恢复：前台重启后出现 SecurityAgent，用户完成钥匙串授权，网络列表恢复；随后登记既有 revision 9，服务界面不再提示登记。没有修改钥匙串 ACL、清除凭据、重启系统 securityd 或切换到明文存储。

## 无法恢复时

若前台重启后仍无提示或拒绝后无法加载，保留原数据并记录版本、现象与不含秘密的诊断。当前网络初始化失败后需要重启 App 才能重试；尚无应用内独立重试入口。网络出站在配置未就绪时保持不可用，不应通过默认直连、重置数据库或删除钥匙串项目来掩盖问题。

正式发布仍需要稳定的签名身份和相应安装/升级验证。内部 ad-hoc 包的授权行为不代表正式签名升级体验已验收。
