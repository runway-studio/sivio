# 系统代理开启后 Google 不通：排查与修复

## 现场证据

- 首页系统代理为开启，但内核为停止：旧快捷开关仅保存设置，未启动网络。
- 手动启动后，macOS HTTP/HTTPS/SOCKS 代理实际指向 Sivio 的 127.0.0.1:7891。
- 同一 Google generate_204 请求：Clash 7890 返回 204；Sivio 7891 在原“美西直连1”节点返回 TLS 连接错误。
- 将 Sivio 当前规则组切换为同订阅、Clash 已验证可用的“香港中转2”后，7891 返回 HTTP 204。选择通过应用保存。
- 曾在系统代理指向 7891 时成功刷新 Chrome Google 页面。
- 后续保留 Clash 的系统代理 7890 作为排障通道；7890 和显式指定 7891 的请求均返回 204。后续验证不关闭 Clash，也不切换全局系统代理。

## 修复

首页快捷开关根据运行状态与系统代理接管冲突显示是否生效。停止时点击开启会在同一个串行设置事务内预检、启动、确认就绪并保存；失败清理候选运行、保留旧设置和停止状态。原设置面板继续只保存停止状态下的设置。系统代理被其他应用接管时显示关闭及原因，用户明确点击开启后调用既有重新接管接口。

保留节点选择，不在后台擅自更换用户节点。当前失效节点属于实测连通性问题，不能仅凭该现象判定整个订阅或代理内核损坏。

## 验证

- 18 项原生设置事务测试通过，包括真实 Mihomo 流量回归、停止状态快捷开启、启动/持久化失败回滚。
- 33 项前端测试通过，覆盖 NetworkHome / NetworkShell / NetworkWorkspace。
- TypeScript 类型检查通过。
- 真实连通性：Google generate_204 经 Sivio 7891 返回 204；Clash 7890 同时保持可用。
