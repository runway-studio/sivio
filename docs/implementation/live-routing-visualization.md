# 路由组实时可视化

入口为「模型 → 路由组」。上方是三栏实时路由图、会话统计、最近一次选路过程，下方为现有路由组列表与编辑器。可以查看所有客户端的活动或聚焦当前客户端的一个组。编辑时保留原有未保存保护。

## 数据和状态

`ProxyService` 共享 `routing_live::Store`，创建 `Recorder` 后开始观察已经成功解析路由组的转发请求。快照只包括原有受限元数据（客户端、组、候选、尝试、模型、排序和额度证据），不保存提示词、输出文本、凭证、URL 或错误正文。未通过鉴权、未能解析组等转发之前的错误不计入路由组统计。

状态来自实际调用：selecting、connecting、streaming、completed、failed、interrupted。响应头被接受时仍保持活动，响应体 EOF 才完成；读错误或可识别的协议错误算失败，取消算中断。SSE 在读到模型字段后继续检查错误信封，覆盖 Anthropic `error`、Responses `response.failed` 和 Gemini/OpenAI 顶层 error 对象；不检查助手内容、不改动转发字节。压缩/超出观察长度/未知协议的错误无法从内容判断，因此界面明确使用“传输完成”，不承诺模型任务完成。

所有计数按客户端和组隔离：请求开始计一次；实际派发从一个成员切换到另一个成员的请求计一次“曾切换成员”；同一成员内重试和熔断跳过不会增加该计数。完成、最终失败、中断互斥，终态重复回调不会重复计数。最后一份 Recorder 的 lease 被释放时标记中断，避免取消后的永久活动状态。网关热重启复用 Store，应用进程重启清零。

最多保留 256 个近期请求，优先保留活动请求；统计累计不随已完成记录淘汰而丢失，最多 512 个客户端/组桶。超过观测容量的请求继续正常转发，界面明确显示未纳入展示和统计的数量。不存在新增数据库迁移，旧路由决策仍兼容。

429 的 `Retry-After` 支持秒数和 HTTP 日期，仅接受当前至 7 天内的建议时间。只展示上游建议，不能据此保证恢复，也不修改原调度策略。没有有效头部时只显示限流，不生成虚构倒计时。

## 页面行为

页面每 750ms 获取当前快照；隐藏或卸载后停止轮询。查询错误或超过 5 秒未刷新时停止动画并显示状态待更新，保留上次快照供查看。动画只用于正在派发或接收响应的路径；静态连线表示组成员关系。`prefers-reduced-motion` 停用动画但保留状态文字。

默认三栏。窄窗口仅在路由图内横向滚动；节点尺寸或侧栏变化后通过 ResizeObserver 测量真实连线端点。图最多 40 个成员，优先当前活动请求，再补最近 12 个完成请求的成员；全部近期观测仍保留于 Store。最近过程可跟随最新请求，也可选择近期请求；展示实际策略、首选原因、每次尝试、HTTP 状态、响应模型及 Smart/Pace 排序证据。组 ID 相同但客户端不同不会混合成员和统计。

## 验证

- 后端请求生命周期：跨客户端隔离、重复回调、取消、流式读错误、协议错误、限流头、容量上限与隐私。
- 隔离 HOME 和本地 HTTP：两个并发 Messages SSE 请求在 EOF 前均保持活动；429 携带 Retry-After 后切换成功，失败终态计数和热重启统计保留。
- 前端组件：并发路径、完成停动画、按客户端/组筛选、排序证据、刷新失败与空态；现有编辑和统一模型选择回归。
- 浏览器：真实 React 页面配合 mock IPC，验证筛选、保存、编辑保护、错误恢复、减少动态效果；zh/en/ja × 两种侧栏状态 × 960/1021/1440 × 浅/深色共 36 组布局。
- 所有验证只使用本地模拟上游，不消耗真实账号额度，也不替代远端服务可用性测试。

最终回归：routing_ 40 项、mode:: 180 项、proxy:: 1,612 项通过（保留 1 项既有忽略测试）；前端 19 项、TypeScript 检查和 36 组浏览器布局通过。后端过滤集合有重叠，不相加作为独立测试数。

报告位于 `build/reports/live-*`。包装沿用独立不可变 App 目录和稳定本地签名；核验报告为 `build/reports/live-routing-package-verified.json`，不覆盖旧 App，不自动安装或重启用户应用。
