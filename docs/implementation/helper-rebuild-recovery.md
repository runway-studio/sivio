# 运行中 App 被打包覆盖导致的服务签名错误

## 根因

2026-10-20 排查发现，正在运行的 Sivio 从 `dist/internal-aarch64/Sivio.app` 启动于前一天，后续打包删除并重建了这个目录。对运行进程执行 `codesign --verify <PID>` 返回 `the code on disk does not match what is running`，对磁盘 App 执行严格签名验证则通过。

服务使用内核 audit token 验证运行中的调用进程；稳定签名证书不能使已经被替换文件的旧进程重新有效。旧进程请求停止、续约及服务状态均可能被拒绝。重新登记服务不会修复旧进程。

## 修复

- 打包复制到 `dist/internal-<arch>/builds/<时间戳与唯一标识>/Sivio.app`，保留所有已有 App，不覆盖运行进程的程序或资源。实际新包路径记录在 `build/reports/app-<arch>-artifact.json`。
- ZIP 和更新压缩包仍输出到原来的架构目录，完成后才替换旧压缩包。不要在应用运行期间手动解压覆盖其目录。
- 未获得服务授权时检查运行进程的动态签名。仅确认代码被替换时提示完全退出并重新打开新版；普通未登记、旧服务、不可信证书等仍走原有服务授权流程。
- 安装服务前也做该检查，避免在无法修复旧进程的情况下重复请求管理员授权。
- 续约错误保留具体原因。停止失败继续保留资源与恢复状态，未放松服务信任、租约、所有权或代理恢复边界。

## 验证

- 打包回归覆盖旧目录保留、两次发布不覆盖资源，以及 macOS 上真实运行进程在第二次发布后仍通过动态签名验证。
- Rust 检查区分代码替换与普通信任错误；前端检查网络页面、设置页正确显示重启提示，并保留真实未授权时的安装入口。
- 最新执行结果、包验证和实机恢复情况记录在 `build/reports/helper-rebuild-*`。
