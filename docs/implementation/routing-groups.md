# Order 路由组（2026-10-20）

用户批准的第一阶段：模型管理菜单新增路由组。每个客户端有独立的命名组，成员为供应商 ID + 明确模型 ID，支持编辑、排序、删除、选择。首版 Order 顺序故障转移，每组 1–10 个不同供应商，每个客户端最多 50 组；不含嵌套、轮换、用量/额度调度或意图路由。

组保存在 SQLite settings 的 routing_groups_<app> 中；编辑持有现有客户端写锁、校验快照修订，阻止陈旧编辑覆盖。ID 为不可变 UUID，重命名不改变请求别名。仅支持 Claude Code、Codex、Gemini CLI、Grok Build 的路由模式；直连/聚合模式必须先显式切换。不支持代理或故障转移的官方账号不能作为成员。

选择器用组别名而非首成员模型表示选中项。Claude 沿用已有设备级 /model 选择及原子文件发布机制；其它客户端将组选择保存于设备 live-state，并随受保护配置投影提交，不写入供应商的直连模型字段。Claude 组列表在应用选择/重新接管时发布；编辑组后重新应用选择可刷新 /model 菜单。旧会话的请求依据组 ID 读取最新成员快照；已删除或无效的组明确失败，不回落到默认上游。

请求上下文一次读取组及成员，成员模型仅覆盖内存中的供应商副本。转发复用原有协议、认证、超时、熔断与错误分类。每个请求最多尝试组内成员数，响应开始后不跨成员拼接流。组内成功切换更新运行统计，但不触发配置路由切换。决策记录保存组名称/ID/成员快照及原有实际尝试，不保存凭据或消息内容。组配置可随常规数据库备份恢复；设备的组选择与其它设备状态保持本地。

验证证据在 build/reports/routing-groups-*：前端表单/导航/选择器回归、真实页面配合 mock IPC 的浏览器流程与 36 组布局、隔离 HOME 配置及本机 HTTP 测试。实际远程供应商及原生 Claude 交互会话不由 mock 浏览器验证替代。

## Rotate / Usage 与选路解释（2026-10-20）

用户确认优先完善 Rotate / Usage 和选路原因。本轮在原有 Order 上新增两种策略，入口仍位于「模型 → 路由组」，创建/编辑后在「模型选择」应用。

- **Rotate**：按入站请求循环选择首选成员；失败后按循环顺序尝试其余成员。
- **Usage**：优先选择本机累计调度次数较少的成员，相同次数按组内配置优先级排序。它不读取供应商 token 消耗、余额或配额。
- **Order**：保持原有优先级顺序，旧组没有 strategy 字段时默认此策略；未知策略明确拒绝。

SQLite schema 22 新增设备本地 routing_group_scheduler 表。事务化预留首选并推进游标，使并发请求不会同时拿到同一个最少计数；首选预留包含后续失败、熔断跳过或取消，备用成员在实际调度时计数，同一成员的整流重试不重复计数。重启、重命名和策略修改保留状态；有序成员/模型指纹变化时重置。组删除与计数清理在一个事务内完成；陈旧配置不能预留，旧请求不能向不同成员配置的计数写入。普通备份保留此表，WebDAV 同步跳过并保留本机表。

决策记录新增 Selection，保存请求预留前的计数与排序结果；页面解释选择依据，同时保留组配置快照与每次真实尝试的 HTTP 状态、模型和耗时。旧记录仍可读取。正常轮换不增加故障切换统计，只有实际转到备用成员时计入；保存的组别名和供应商直连模型均不被运行调度覆盖。Claude /model 菜单描述会展示所选策略。

调度单位是请求，不提供上游私有会话 ID 跨供应商迁移。只传 previous_response_id 而不带上下文的原生 Responses 续接仍依赖上游保存的会话，不能据此保证跨供应商连续会话；本轮本机 HTTP 验收覆盖完整消息请求、故障转移和客户端配置重启。Smart / Pace 仍待可靠的账号额度数据接入，不作为已实现功能展示。

验证证据：`build/reports/routing-strategies-*`。前端类型检查、11 项组件回归；浏览器使用真实 React 页面和 mock IPC 验证创建、排序、修改策略、未保存编辑保护、统一选择器应用及记录解释，覆盖中/英/日、侧栏展开/收起、960/1021/1280 宽度、明暗主题共 36 组布局。后端隔离 HOME 与本机 HTTP 验证四类客户端的成员模型和凭据、429 备用、策略连续请求、重启与选择保留，并验证 SQLite 重开、30 并发请求分配、配置变更、同步隔离、旧记录解码。测试不修改用户现有客户端配置，不消耗真实供应商额度。

本轮最终回归结果：路由定向 26 项、模式 178 项、数据库 106 项、代理 1,607 项通过；数据库 2 项和代理 1 项原有忽略测试保留。各测试集合存在重叠，不作为独立测试总数相加。打包核验报告为 `routing-strategies-package-verified.json`，包括 Apple Silicon 架构、稳定本地签名、解包后签名、对应源码及资源一致性。

## Smart / Pace（2026-10-20）

用户授权继续实现并打包。参考 Magpie 官方 README 的 [Routing groups](https://github.com/yetone/magpie#routing-groups) 定义：Smart 优先使用仍有额度、最早重置的成员；Pace 按周剩余百分比除以剩余小时数排序，多个周窗口取最保守速率，分母最少一分钟。同分按配置顺序。原有 Order / Rotate / Usage、组别名及模型重启恢复保持不变。

### 数据来源与边界

- 明确绑定的 Codex OAuth / ChatGPT 账号：复用现有账号管理器和额度查询。缓存键包含认证身份/时间和 workspace 的内存指纹；查询前后核对身份，不沿用默认账号或应用级 CLI 订阅缓存。
- 已识别官方 HTTPS 域名、使用实际推理密钥的 Kimi Coding、智谱个人套餐、MiniMax、ZenMux、OpenCode Go、Command Code。不存在官方窗口时显示不可评分，不以 API 余额或脚本字符串代替。
- 另行配置的用量密钥或地址与实际推理配置不一致时，不参与额度排序。火山独立控制面凭据、智谱团队组织/项目配额未证明与实际请求相同作用域，暂不接入；不把供应商名称、URL 子串或其他客户端的订阅信息作为账号绑定证据。
- Kimi 容量字段和 ZenMux 使用百分比缺失时明确失败。智谱的路由解析只用显式单位确认周窗口，不使用展示层的历史猜测。Command Code 的月度余额推导值不用于路由，只接受明确的滚动窗口。
- 不增加跨供应商私有会话 ID 迁移或会话粘性，沿用上轮按请求调度的协议边界。

### 调度与解释

Smart/Pace 请求自动收集额度，不需要打开用量页面。最多 10 个成员并发查询，各查询最多等待 3 秒（网络取数限 2.5 秒，其余预算包含并发锁等待）；同一缓存项合并并发刷新。成功缓存 60 秒、失败/超时缓存 15 秒，最多 256 项，仅保存在进程内。跨越重置点主动刷新；超过五分钟、未来采样时间、非法百分比和已过重置点的快照不评分。应用重启清空额度缓存，代理服务热重启保留仍有效缓存；其他三种策略不触发额度请求。

查询在 SQLite 事务外进行；查询完成后核对成员凭据/绑定，选路事务再核对组配置。有效候选在前，未知数据按配置顺序兜底，已知耗尽成员最后尝试（保留供应商自己的超额付费或恢复能力）。无可评分额度时记录明确的优先级兜底原因。运行选择不修改已保存的组别名、成员模型或供应商直连配置。

决策记录显示来源、状态、采样时间、选中的窗口、剩余百分比、重置时间及 Pace 评分，并保留实际尝试链。所有未知/过期/失败状态可见，记录不包含密钥、账号标识、URL、提示词或上游原始错误。旧记录缺失新增字段时仍可读。入口仍在「模型 → 路由组」和「模型 → 路由决策记录」，Claude /model 菜单使用对应策略描述。
